# 搜索预算与失败恢复

本轮改进的是 **Render 个人服务的预算执行可靠性**。GitHub Actions 公共任务和其他共享 Brave key 的应用仍有独立账本，不能把这里的上限当作供应商账户总额度或账单。

## 已实现

1. **调用前持久预留**：检查个人/服务全局剩余额度，预留本次上限后才允许外部请求。在真正的 HTTP 请求边界再次检查预算上限，并记录实际尝试数，不能只依赖上层模块自报。正常完成取合法自报数与边界观察数的较大值结算；失败、进程中断或计数异常不自动释放不确定的预留。原个人/全局默认 4/6 次每日上限保持不变。
2. **落盘顺序**：临时文件以 0600 权限写入，先 `fsync` 文件，再 rename 正式文件，最后 `fsync` 父目录。任何持久化失败都返回错误，不把尚未保存的结果报告为成功，也不继续发起搜索。JSON/额度格式损坏时拒绝读取，不重置为新账本。首次成功写入会同步初始化标记；标记还在但账本丢失时同样拒绝服务，不能误当成首次安装清零。
3. **跨进程文件互斥**：Linux `flock` 锁覆盖完整操作，每次持锁后重读磁盘状态，避免不同进程缓存彼此覆盖。进程被杀后由操作系统与关闭的管道释放锁；不通过删除锁文件或“超时抢锁”冒险接管。获取锁最多等待 5 秒；同进程默认最多积压 64 个操作。
4. **幂等请求**：App 在发起搜索前把随机 requestId 与关键词签名存入本机。同一用户、相同 requestId、相同参数在 24 小时保留窗口内重放已完成结果，不再次调用供应商；相同标识配不同参数返回409。每设备最多保留20个窗口内任务记录。过期后标识可作为新任务处理；前端也会为过期动作创建新标识。
5. **中断恢复**：持锁重读时，遗留 running 记录标记 interrupted，保留旧日报与已预留额度，不自动重复该请求。前端收到明确终止状态后清除挂起标识，下一次用户点击才创建新任务。
6. **跨日保护**：每次真正发起 Brave 请求前检查北京时间日期，日期改变后停止旧任务的新请求，防止继续使用昨日预留。计数按请求发起时间定义，不能代表供应商在途请求的入账日或计费口径。
7. **定时退避**：失败/中断记录保存最早重试时间（30分钟），定时任务跳过尚未到期或个人额度已经耗尽的用户；旧日报保留。手动创建新任务仍受额度约束。
8. **兼容性保护**：`/api/status` 增加 `budgetPolicyVersion: 2`，新版 App 不向旧后台提交付费搜索，避免前端已使用幂等标识、旧后端却忽略。旧 API 客户端不提供 requestId 时仍可创建新动作，但不享有相同动作自动重试的幂等保证。

## 部署

Dockerfile 安装 Linux `util-linux`，提供 flock；没有增加数据库或付费云资源。沿用现有 Render 常驻服务与 `/var/data/personal.json` 持久磁盘。升级前建议由管理员保留状态文件备份；没有自动覆盖、清空或迁移到新路径。旧格式在保持额度的前提下按需加入任务记录。

如果 App 提示后台版本较旧，在 Render 服务选择 Manual Deploy → Deploy latest commit，等待 Live 后重连。不要通过删除状态文件、移除持久磁盘或改路径来修复额度错误。状态损坏时应先停调用，再对照供应商记录恢复可信账本；旧备份不一定包含后来消费的额度。

本地后端使用 Linux 或项目 Docker 镜像，需有 flock；macOS/Windows 推荐使用 Docker。`PERSONAL_FLOCK_BIN` 可指定管理员已安装的兼容 flock 路径，不接受客户端传入。

## 仍需区分的边界

- 文件锁仅保护**同一台系统、同一个支持 advisory lock 的文件系统与状态文件**。不同磁盘的副本、分布式网络文件系统、多地区服务没有因此获得共享额度；正式横向扩容仍应迁移到事务数据库/集中预算服务。
- fsync 是操作系统持久化保证，不替代云磁盘备份，不能防止管理员删除卷、回滚旧快照或硬件故障。
- 幂等窗口是24小时，并非永久 exactly-once。超时后不要换标识自动重试；新用户动作与同一 key 的其他服务仍会产生新的调用。
- 查询计数和失败时预留均可能高于实际计费数量，尤其任务中断时；不自动退款是保守策略。供应商余额、月账单及其日界线以供应商为准。
- 当前仍以同步、有界串行执行为主。大量用户的任务排队、异步任务状态轮询、共享数据库和统一账户预算，是下一阶段的扩展工作。
- 本轮不改变岗位来源访问许可、规则评分或模型接入状态。BOSS 授权数据、稳定结构化来源和评分效果验证仍是独立缺口。

## 验证

单元测试覆盖文件/目录同步顺序、写盘故障不发请求、结算失败保留预留、状态损坏拒绝服务、两个独立服务实例争用额度、同请求跨重启重放、跨日停止新请求、队列反压及**子进程 SIGKILL 后重启**。浏览器测试模拟响应丢失、重新打开页面及复用请求标识，确认不会模拟执行第二次同一供应商动作；原档案、偏好、评分、收藏、来源质量和手机/电脑回归继续执行。全部测试使用模拟供应商，不消耗真实搜索额度。
