# 从共享岗位池升级为用户自主检索

## 已实现的使用流程

每位用户打开网站或 PWA，在“求职偏好”填写目标岗位、城市、薪资、用工类型、工作方式、求职阶段和排除词。连接个人服务后，“保存我的日报需求”会保存该设备的后台检索条件；“更新我的岗位日报”按这些条件实际调用搜索服务，不修改仓库的 JOB_ROLE / JOB_CITY / JOB_REGION。

勾选“启用我的每日检索”后，在线后台在北京时间 08:00 后每分钟检查待更新用户，并在额度允许时生成新日报。关闭 App 不影响常驻后台；若服务器停机，恢复后补查当日任务。取消勾选并保存可停止自动检索。撤销关键词发送同意并保存时，不发送新关键词，并停用该设备定时检索；删除服务端数据使用单独的删除按钮。

姓名、年龄、性别、完整经历和获奖经历不发往后台。用户同意后，仅发送筛选和检索关键词，包括技能、专业。完整个人档案、评分、收藏和正文导入继续保存在本机。个人需求及岗位结果保存在服务器私有数据卷，不写入公开 GitHub 岗位索引。

当前通过随机设备凭证隔离用户空间：不同浏览器/PWA 设备互相看不到日报。服务端仅存凭证哈希。会话 30 天有效，保存需求会延长有效期。尚不提供账号登录、跨设备同步或找回；清除设备凭证前可点击“停用并删除服务端日报”。过期数据会在服务检查时清理。

## 你没有服务器时：用 Render 部署

仓库已提供 `Dockerfile` 和 `render.yaml`，可以部署完整网站和个人后端。**自动每日更新和重启后保留个人日报，需要常驻实例及持久磁盘。该配置使用 Render 的 starter 套餐和 1 GB 数据盘，属于收费资源，开通前请在平台确认显示的价格。代码不会代你购买或创建服务。** 免费休眠实例可用于手动搜索试用，但不能保证每日后台执行和本地文件持久化，不作为本配置的正式运行方案。

1. 打开 https://render.com/deploy?repo=https://github.com/winne-wang0505/resume ，登录 Render 并授权读取这个仓库。如未进入 Blueprint 创建页，在 Dashboard 中选择 New → Blueprint，再选 `winne-wang0505/resume`。
2. 确认服务方案和磁盘价格。`BRAVE_SEARCH_API_KEY` 填入现有 Brave key；不要把 key 发到聊天、前端配置或公开仓库。其他变量由 Blueprint 提供。确认后创建服务。
3. 等待状态为 Live，复制 `https://……onrender.com` 地址。**直接打开这个地址就是完整 App，无需另外连接，所有用户可使用同一个网址，各自保存和搜索自己的需求。** PWA 安装、档案、收藏等仍可用；原 GitHub Pages 的本机数据不会自动迁移到新域名。
4. 若希望继续使用原 GitHub Pages 地址：在“求职偏好 → 我的岗位日报服务 → 连接个人检索服务”填写该服务地址并连接。Render 的 `APP_ORIGINS` 默认已允许 `https://winne-wang0505.github.io`（是 origin，不含 `/resume/`）。
5. 管理员可把 `public/service.json` 的 `apiBase` 改为该 HTTPS 服务地址并提交发布；之后其他 GitHub Pages 用户会自动发现服务，不必逐人填写地址。该文件只能存公开服务 URL，不能存 API key 或设备凭证。
6. 在 App 填写求职偏好、同意发送检索关键词，保存需求，点击“更新我的岗位日报”；要自动更新，再勾选“启用我的每日检索”并保存。

GitHub 的 Actions secret 不能自动传给 Render；第 2 步需要在 Render 私密环境变量中配置同一个 key。部署前界面会明确显示未连接，仍保留共享公开日报，不会把本机筛选伪装成真实个人检索。

## 默认额度与持久化

- `PERSONAL_DAILY_BUDGET=6`：此服务所有用户合计每天最多 6 次搜索 API 请求。
- `PERSONAL_USER_BUDGET=4`：单个设备用户每天最多 4 次；实际还受全局剩余额度限制。一次搜索按钮可能发出多次请求，界面显示的是搜索请求额度。
- 一次最多 3 个岗位方向；个人即时检索默认最多 1 页、12 次新详情读取，并保留仍可参考的个人历史岗位。原公共日报策略保持原值。
- 额度耗尽返回明确提示并保留已有日报；次日北京时间重置。定时更新先处理较久未更新用户，额度不足的用户顺延，不能保证默认小额度服务每天覆盖大量用户。
- 6 次是较小的启动额度；多人正式使用应由管理员根据 Brave 套餐调整，不在客户端给用户无限额调用权限。个人服务额度与 GitHub Actions 公共检索额度分别计数，供应商实际账单为准。
- `PERSONAL_STATE_FILE=/var/data/personal.json` 在持久磁盘上保存需求、岗位和额度。请求前先持久化预留额度；失败会保守占用预留额度，避免重启或重试绕过限额。不会在失败时删除旧日报。
- 目前使用单进程文件状态和串行搜索队列。只部署一个实例；多实例、海量用户、正式账号体系需要共享数据库/队列升级，不能用多个副本共享此文件模拟扩容。
- `TRUST_PROXY=true` 仅用于 Render 等受信任代理之后。自己部署且端口直连公网时应为 false。会话签发有网络频率限制，不依赖前端传入的用户 ID。

## API

- `GET /api/status`：只返回个人检索是否配置。
- `POST /api/session`：发放随机设备凭证，服务端保存哈希。
- `GET /api/personal`：认证后读取本设备需求、日报和额度。
- `PUT /api/personal`：认证后保存允许的检索关键词和每日更新开关。
- `POST /api/search`：认证后按个人条件检索；API key 仅在后台。
- `DELETE /api/personal`：删除本设备服务端数据并停用自动检索。

除 status 和签发 session 外均需 `Authorization: Bearer <设备凭证>`。跨域只接受 `APP_ORIGINS` 中的前端 origin 或同源请求。设备凭证自动保存在本机，不应人工复制到服务配置。

## 验证

`npm test` 覆盖用户隔离、关键词允许列表、同意授权、需求修改驱动真实搜索调用、定时开关、08:00 规则、跨日/重启额度、失败保留、会话删除和 HTTP/CORS 认证。`npm run test:ui` 除原功能回归外，检查两个独立设备的不同需求、个人搜索、自动更新开关与刷新恢复。
