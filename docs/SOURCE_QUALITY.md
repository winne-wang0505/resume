# 精选来源与岗位有效性

## 当前策略

默认停止轮换大量入口（注册表现保留 42 个），改为精选双来源：内地猎聘、香港 OfferToday。猎聘已在运行中取得完整正文；OfferToday 新增为公开详情适配候选，支持 HTTPS 允许列表、单岗位识别、JobPosting 和保守正文解析，尚不能承诺其每个页面可自动读取。来源数量不代表 API 接入或完整数据量。

App“求职偏好 → 岗位来源”也可选择“BOSS／OfferToday”。BOSS 已观察到 robots 限制，**没有取得授权数据前不会自动读取或绕过限制，也不会偷偷扩大到其他平台补数量**。该模式可能只有香港公开结果，或没有可推荐结果。BOSS 岗位可以在正常访问平台后，粘贴单个岗位正文到本机分析。未来取得授权 feed/API 后才能替换这一限制；当前没有猜测或调用私有接口。

默认精选模式是为了保留已有可用数据作为兜底。用户可在界面自行切换；保存个人需求后，再点击更新个人日报。取消关键词同意仍停止后台定时任务。公共任务 `JOB_SOURCE_MODE` 默认 standard，也可设 preferred；broad 仅作为旧接口/测试兼容模式，不在普通 App 中提供。

## 什么会直接剔除

- 详情链接返回 404 或 410。
- 页面明确显示岗位下架、关闭、已招满、停止接受申请等信号，即使完整职位字段缺失或旧 JobPosting 仍存在。
- 公告截止日期已过，按内地/香港 UTC+08:00 处理整日截止时间。
- 同样规则用于初次发现、历史复核、公开旧索引、个人服务读取及本机缓存，不能通过“待核实”重新混入推荐。

访问受限、HTTP405、验证码和动态页面不等于下架，不能伪造失效结论；这些问题只进入折叠来源诊断。相关职位推荐区的下架提示不应误删当前仍有效岗位。

已知下架链接保存 7 天排除记录；即使搜索引擎仍返回该链接，也跳过详情读取，减少重复无效请求。7 天后允许重新检查，避免永久阻止同 URL 重新开放的岗位。搜索引擎本身仍可能返回旧链接，不能保证从第三方索引中立即消失。

## 推荐门槛与时效

- 自动推荐需要明确职位、雇主、地点、至少 80 字符正文以及可用于匹配的学历、经验或技能要求。
- 发布超过 30 天且无截止日期的自动岗位暂不推荐，不据此伪造“已下架”结论；有明确未来截止日期的长期公告保留。
- 自动详情读取时间不得超过 24 小时；超过后暂不推荐，只保留为折叠诊断/历史记录，等待后台重读。
- 个人“更新我的岗位日报”会绕过旧详情缓存，并复核有限数量历史岗位。并发和额度上限仍保留；没有读到的旧岗位不能被标成新近核验。
- 薪资、截止日期等未披露字段保留“未披露”，不编造；公开页读取成功不保证岗位在之后仍持续开放。投递前仍需打开原公告确认。
- 用户粘贴正文单独标注来源未验证，不冒充自动读取；已知过期或下架时同样剔除。
- 已收藏的投递记录保留，失效时显示已截止，不自动删除用户的投递历史。

新增单元及浏览器测试覆盖：只有下架提示的页面、残留结构化数据、404/410 首次发现、历史与缓存清理、相关职位误判、时区截止日期、七天排除记录、个人即时重读、24 小时门槛、限定来源，以及诊断默认折叠。原有个人需求、隔离、额度、评分、收藏和 PWA 回归继续执行。

后端 `/api/status` 提供 `sourcePolicyVersion: 1`。新 App 不向旧版本后端提交精选搜索；若提示版本较旧，请在 Render → Manual Deploy → Deploy latest commit 更新服务，再重新连接。
