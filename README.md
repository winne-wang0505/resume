# 职向 · Career Compass

面向中国内地与香港的求职规划工作台：响应式网站 + 可安装 PWA。可运行的第一版使用可解释规则分析，不宣称掌握所有行业或预测录用率。原有 PDF 文件未改动，也不会被网站公开打包。

## 当前能力与边界

- 个人档案：学历、专业、毕业年份、技能、语言、工作／实习／项目经历、奖项、到岗时间、作品集与香港工作许可。年龄和性别为可选信息，不参与排序。
- 求职偏好：地区、城市、岗位、机构类型、月薪及币种、办公方式、用工类型、时间、专业与工作内容、排除关键词。
- 岗位页：内地／香港切换，央国企、外企、私企、公务员／公共机构、事业单位／高校、非营利组织等筛选，搜索、排序、来源与更新时间。
- 分析：0–100 匹配度、竞争准备度、投递性价比、信息覆盖度、缺失技能、门槛提示与行动建议。没有要求的数据不伪造分数，不把信息缺失当成满足。
- 收藏、投递状态、应用内每日简报、本机数据清除。
- 可选 Brave Search API 实时检索；可选 GitHub Actions 每日检索与应用内简报。**没有配置凭据时这些外部功能不运行。**
- 现附 4 条明确标记的演示数据，不计入真实每日推荐和优先岗位数量。

当前是单用户工作台：无账户、跨设备同步、多用户数据库、原生 iOS/Android 包、后台 Web Push 或付费大模型对话。PWA 可安装到手机／电脑主屏幕，不能等同于 App Store 原生应用。工作时间和专业等偏好参与检索，但只有已披露的结构化条件才能可靠评分。

## 本地启动

Node.js >= 22，无第三方运行时依赖，无需 npm install。

```sh
cd /workspace/resume
npm test
npm run build
npm run dev
```

默认监听 `127.0.0.1:3000`。局域网／容器使用 `HOST=0.0.0.0 npm start`。公开部署后台时请在前置网关配置认证、按用户限流、HTTPS；内置的全局 10 秒检索间隔只适合单用户开发。不要在客户端填写 API 密钥。

需要实时搜索时，从 `.env.example` 创建**未跟踪**的 `.env` 并在本机安全填值，再运行：

```sh
node --env-file=.env server.mjs
```

保存个人档案与偏好，并勾选允许发送检索关键词后点击“检索最新岗位”。`GET /api/status` 仅返回配置状态；`POST /api/search` 仅接受同源 JSON 请求。服务器只转发白名单偏好、技能与专业字段，不发送姓名、性别、年龄、完整经历。

## 真实岗位检索与来源

`src/search.mjs` 以用户的岗位、城市、技能、专业与偏好自动构建近一个月的搜索请求。来源白名单：

- 内地：智联、猎聘、前程无忧、国聘、国资委、人社部、国家公务员局及政府网站。
- 香港：JobsDB、CTgoodjobs、劳工处、公务员事务局、公务员招聘网站、Indeed 香港。

搜索摘要只是**待核实招聘线索**，可能为汇总页或过期招聘，不是已核实的在招职位。不会从摘要猜测雇主、薪资、经验或机构类型。搜索发现时间不等于招聘发布时间；有 API 凭据后仍须通过实际服务验证可用性。当前尚未验证真实搜索 API。

用于评分的详细数据需要官方许可的结构化岗位源或人工核验补充。本版本未实现各招聘网站的登录抓取、付费数据接口或通用网页抽取；不会绕过登录或反爬限制。增加来源应保留原始 URL、采集时间、截止日期、币种及明确要求。不同网站的字段完整度无法保证。

## 评分口径

`src/match.mjs`：技能 35、学历 15、经验 20、城市 10、同币种薪资 15、办公方式 5。只对有资料的维度归一化，覆盖度单独展示。薪资以月薪为标准，不做未经证实的汇率或年薪转换。

竞争准备度 = 匹配度 × 0.85 + 有填写成果 10 分 + 有填写经历 5 分。填写本身不等于核实成果质量，因此只作为准备提醒。性价比 = 匹配度 × 0.65 + 准备度 × 0.25 + 时间便利度 × 0.10，硬性门槛不满足扣 15 分；申请时间默认 30 分钟，是可调整的规划假设。75 分及以上优先，50–74 选择性投入，低于 50 建议先补齐差距；门槛和截止日期提示优先于总分。

**不是候选人排名、录用概率或薪酬承诺。** 缺少申请人数、候选人分布等数据时不能计算真实竞争强度。专业、语言、签证、公共部门资格及专业考试要求须核验原公告；年龄、性别不用于评分。未披露条件不代表没有限制。

## GitHub 网站部署

1. 推送到 `main`。仓库 Settings → Pages → Build and deployment 选择 **GitHub Actions**。
2. `.github/workflows/pages.yml` 执行测试、构建并发布 `dist/`。
3. 项目 Pages 通常为 `https://winne-wang0505.github.io/resume/`；以 Actions 成功部署后的实际地址为准。代码推送成功不能代表网页已经发布。
4. 网站所有资源使用相对路径，可部署到仓库子路径。`dist/` 不包含 PDF、测试、环境文件或服务端密钥。
5. iOS Safari：分享 → 添加到主屏幕；Android Chrome：安装应用／添加到主屏幕。桌面 Chrome/Edge 可从地址栏安装。需要 HTTPS。浏览器安装兼容性应在目标设备验证。

GitHub Pages 只有静态文件，没有 Node API。在线网站的“实时检索”需要把整个应用部署到可运行 Node 的服务器，或通过每日任务更新静态索引。不要把密钥写入 Pages、仓库变量中的公开配置或浏览器。

## 每日自动推荐（仅应用内）

`.github/workflows/daily.yml` 每天北京时间 08:00 调度（GitHub 可能延迟，低活跃公开仓库也可能停用定时任务）；支持手动触发。运行 `npm run jobs:refresh` 更新公开索引并重新部署 Pages。没有搜索密钥会明确失败，保留现有索引；部分地区失败也保留旧索引，不掩盖失败。

在仓库 Settings → Secrets and variables → Actions 配置：

| 类型     | 名称                       | 用途                                |
| -------- | -------------------------- | ----------------------------------- |
| Secret   | `BRAVE_SEARCH_API_KEY`     | Brave Search API 密钥，必需用于检索 |
| Variable | `JOB_ROLE`                 | 目标岗位，默认“数据分析”            |
| Variable | `JOB_REGION`               | `全部`、`内地`、`香港`              |
| Variable | `JOB_CITY` / `JOB_EXCLUDE` | 城市／逗号分隔排除词                |

按照用户选择，仅在应用内展示推荐，不实现邮件发送。浏览器“导出偏好”只导出偏好，不包含经历，也不会自动同步到 Actions。定时公共索引按 JOB_* 检索，打开应用时再按当前设备个人档案生成个性化评分与简报；静态站点不能在关闭时持续执行个性化后台任务。每日任务不执行自动投递。

## 隐私与生产化建议

个人资料存于浏览器 localStorage，没有服务端存储或跨设备同步。同一域名下脚本可以读取，勿在共享设备长期保存敏感数据。检索服务只收到偏好、技能和专业白名单关键词；来源链接会在新窗口打开。网页不加载第三方字体或分析脚本。可在侧栏或个人档案页清除本机数据；清除操作不能删除已导出的文件。

多用户上线前需要账户认证、加密数据库、用户时区和定时订阅、退订、可靠队列、按账户鉴权限流、合规的数据来源及结构化职位校验。评分是透明的规则版，需要行业数据与用户反馈后再校准。

## 验证

`npm test` 覆盖高匹配、缺失信息、年龄性别不参与、不同币种、资格门槛、截止日期、URL 安全、关键词最小化、来源过滤、重复去除、搜索失败及部分失败。`npm run build` 输出静态网站。真实搜索、GitHub Pages 与手机安装必须在凭据、平台权限和目标设备具备后单独验收。
